# MCP OAuth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let claude.ai's connector UI authorize against the tracker via OAuth 2.1 (PKCE + dynamic client registration), minting the existing `fpt_` tokens so `/api/mcp` and `/settings` token management work unchanged.

**Architecture:** Spec §"MCP integration" → "Auth for claude.ai connectors" is the contract — read it first. New: migration 0013 (`oauth_clients`, `oauth_codes`), `src/lib/oauth.ts` (pure PKCE/validation helpers + server flows), discovery routes, register/token route handlers (public), session-gated authorize page with a plain-POST approve route, `?next=` support on `/login`, `WWW-Authenticate` on `/api/mcp` 401s.

**Tech Stack:** node:crypto (S256), existing admin client + api-tokens lib. No new deps.

## Global Constraints

- Access token = `generateToken()` `fpt_` token inserted into `api_tokens` with name `"<client_name> (OAuth)"` — nothing about `/api/mcp` auth changes.
- PKCE required, S256 only (`code_challenge_method=S256`; reject `plain`). Codes: 32 random bytes base64url, sha256-stored in `oauth_codes`, single-use (`used` flag flipped transactionally — check-and-set via `.update().eq("used", false).select()` to prevent replay), 10-minute expiry, bound to client_id + redirect_uri + user_id + code_challenge.
- redirect_uri: EXACT string match against the registered list, https-only except `http://localhost`/`http://127.0.0.1` prefixes.
- `/login?next=` accepts only values matching `/^\/[a-zA-Z0-9_\-/?=&%.]*$/` and not starting `//` (open-redirect guard); both password and magic-link paths honor it (magic link via `emailRedirectTo` carrying next through `/auth/callback?next=…`, callback validates again).
- Middleware PUBLIC_PATHS additions (boundary-safe): `/^\/\.well-known\//`, `/^\/oauth\/register$/`, `/^\/oauth\/token$/`. `/oauth/authorize` stays protected (session required is the point). The `?next=` redirect enhancement lives in the middleware's redirect construction.
- OAuth error responses per RFC 6749: JSON `{error, error_description}` with correct status (400 invalid_request/invalid_grant, 401 invalid_client).
- `oauth_clients`/`oauth_codes`: RLS enabled, NO policies (browser roles denied), grants only to service_role. pgTAP proves authenticated gets permission denied.
- Migration numbering: `20260812000013_oauth.sql`.
- All server flows use the admin client via `src/lib/oauth-server.ts` (split pure vs server like api-tokens; vitest imports only the pure module).

### Task 1: Migration + pure OAuth lib

**Files:** migration 0013 + pgTAP 006; `src/lib/oauth.ts` + `tests/oauth.test.ts`.

**Interfaces:**
- Tables: `oauth_clients(id uuid pk default gen_random_uuid(), client_name text not null, redirect_uris text[] not null, created_at timestamptz default now())`; `oauth_codes(id uuid pk default gen_random_uuid(), code_hash text not null unique, client_id uuid not null references oauth_clients(id) on delete cascade, user_id uuid not null references profiles(id) on delete cascade, redirect_uri text not null, code_challenge text not null, expires_at timestamptz not null, used boolean not null default false, created_at timestamptz default now())`. RLS enabled, zero policies; `grant select, insert, update, delete on oauth_clients, oauth_codes to service_role;` ONLY.
- pgTAP 006 (plan 4): has_table ×2; as authenticated: `throws_ok` 42501 selecting from each.
- `src/lib/oauth.ts` (pure, node:crypto only):
  - `sanitizeNext(next: string | null): string` → next if it matches the Global Constraints pattern and !startsWith("//") else "/".
  - `validateRedirectUri(uri: string, registered: string[]): boolean` — exact match + scheme rule.
  - `verifyPkce(verifier: string, challenge: string): boolean` — base64url(sha256(verifier)) === challenge; verifier charset per RFC 7636 (43–128 chars) enforced.
  - `randomCode(): { code: string; hash: string }` — 32B base64url + sha256 hex.
- Vitest (write first, RED→GREEN): sanitizeNext (["/settings"→ok, "https://evil.com"→"/", "//evil"→"/", null→"/"]); validateRedirectUri (exact match yes; prefix no; http non-localhost no; http://localhost:3000/cb yes); verifyPkce (known RFC 7636 appendix vector: verifier "dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk" ↔ challenge "E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM"); randomCode shape.

**Steps:** pgTAP RED → migration → `npx supabase db reset && npx supabase test db` green (recreate dev user + `npm run seed` after) → vitest RED → lib → GREEN → commit `feat: oauth tables and pure pkce/redirect helpers`.

### Task 2: Server flows + login `next` round-trip

**Files:** `src/lib/oauth-server.ts`; middleware `?next=`; `src/app/login/page.tsx`; `src/app/auth/callback/route.ts`.

**Interfaces (oauth-server.ts, all admin client, `import "server-only"`):**
- `registerClient(input: unknown): { client_id, client_name, redirect_uris } | { error: string }` — validate client_name string ≤100, redirect_uris non-empty array of valid-scheme URIs (each must pass the scheme rule), insert, return.
- `getClient(clientId)`; `createAuthCode(userId, clientId, redirectUri, codeChallenge): string` (returns plaintext code; stores hash, expires now+10min); `exchangeCode({ code, client_id, redirect_uri, code_verifier }): { access_token } | { error, status }` — lookup by hash where `used=false` AND unexpired via check-and-set update returning the row (replay-safe), validate client + redirect_uri + `verifyPkce`, then mint via `generateToken()` + insert `api_tokens` (user_id from code row, name `"<client_name> (OAuth)"`), return token.
- Middleware: on unauthenticated redirect, set `url.pathname = "/login"; url.searchParams.set("next", originalPathnameAndSearch)` (only when original path isn't "/"); PUBLIC_PATHS additions per Global Constraints.
- Login page: reads `next` via useSearchParams (wrap relevant part in Suspense if Next requires), passes through `sanitizeNext`; password login → `window.location.href = next`; magic link → `emailRedirectTo: ${site}/auth/callback?next=${encodeURIComponent(next)}`. Callback: `redirect(origin + sanitizeNext(searchParams.get("next")))`.

**Steps:** implement; `npm test` stays green; build; headless check: `curl -s -o /dev/null -w "%{redirect_url}" localhost:3000/oauth/authorize?x=1` → login redirect containing `next=%2Foauth%2Fauthorize`; commit `feat: oauth server flows and login next-param round-trip`.

### Task 3: Routes + consent page + discovery + WWW-Authenticate + connect copy

**Files:** the six route/page files from File Structure; `/api/mcp` 401 header; TokenManager copy.

**Interfaces:**
- `/.well-known/oauth-authorization-server` (GET, public): `{ issuer: SITE, authorization_endpoint: SITE+"/oauth/authorize", token_endpoint: SITE+"/oauth/token", registration_endpoint: SITE+"/oauth/register", response_types_supported: ["code"], grant_types_supported: ["authorization_code"], code_challenge_methods_supported: ["S256"], token_endpoint_auth_methods_supported: ["none"] }` where SITE = NEXT_PUBLIC_SITE_URL. Also serve the same doc at `/.well-known/oauth-authorization-server/api/mcp` (path-suffixed discovery some clients probe) — same handler via a `[[...slug]]` segment or duplicate route.
- `/.well-known/oauth-protected-resource` (+ `/api/mcp` suffix variant): `{ resource: SITE+"/api/mcp", authorization_servers: [SITE], bearer_methods_supported: ["header"] }`.
- `POST /oauth/register`: JSON body → registerClient → 201 with `{ client_id, client_name, redirect_uris, token_endpoint_auth_method: "none" }`; 400 with `{error:"invalid_client_metadata", error_description}` on validation failure.
- `GET /oauth/authorize` (server component, session guaranteed by middleware): validate query (`response_type=code`, known client_id, exact redirect_uri, `code_challenge` present, `code_challenge_method=S256`); invalid → render an error page (NEVER redirect to an unvalidated redirect_uri). Valid → consent card: app name, client_name, "wants to access your Farsi tracker", Approve (form POST to `/oauth/authorize/approve` with hidden fields) + Cancel (redirect_uri?error=access_denied&state).
- `POST /oauth/authorize/approve` (route handler, session required — re-check via createClient().auth.getUser(); 403 if none): re-validate everything server-side (client, redirect_uri, challenge), `createAuthCode`, 303 redirect to `redirect_uri?code=…&state=…`.
- `POST /oauth/token` (public, accepts BOTH application/x-www-form-urlencoded and JSON): grant_type must be authorization_code → exchangeCode → `{ access_token, token_type: "bearer" }` (200, `Cache-Control: no-store`) or RFC-shaped error JSON.
- `/api/mcp` 401s add header `WWW-Authenticate: Bearer resource_metadata="${SITE}/.well-known/oauth-protected-resource"`.
- TokenManager connect instructions: claude.ai section becomes "Add custom connector → paste ${origin}/api/mcp → complete the sign-in/consent screen. No client ID or secret needed." (Claude Code static-token instructions stay.)

**Steps:** implement; build; headless: curl both well-known docs (assert JSON keys); register a client via curl → 201; authorize unauth → redirects to /login with next; token with garbage → RFC error shape; `npm test` green; commit `feat: oauth authorize/token/register routes, discovery, consent page`.
